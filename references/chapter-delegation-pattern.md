# 章节写作委托模式

> 从 no003 项目中总结的章节批量写作最佳实践。

## 委托模式

### 批量大小：3章/批

每批委托写3章，原因：
- 每章 ~8000 字符 = 每批 ~40K 字符
- 在子代理上下文窗口内
- 保持批次内风格一致
- **实测验证**：5章/批经常触发迭代上限（max_iterations），3章是安全阈值
- 超过3章容易超时，超时后检查已写入文件，从断点继续

### 委托模板

```python
delegate_task(
    goal="""你是一个网文写手，擅长修仙小说。请阅读以下文件：
1. 大纲文档路径
2. 章节大纲路径
3. 前一批最后2章（用于风格延续）

然后写第N章到第N+2章，每章5000字以上。

**大纲要求**：
- 简述这批章节的剧情走向

**具体剧情点**：
- 第N章：...
- 第N+1章：...
- ...

**写作要求**：
- 每章5000字以上
- 风格：...
- 节奏：每章起承转爽，结尾有钩子
- 保持与前文一致的风格和人物设定

将完整章节写入：
- 路径/第XXX章-标题.md
- 路径/第XXX章-标题.md
- 路径/第XXX章-标题.md
""",
    context="项目路径、世界观文档路径、大纲路径、前文路径",
    role="leaf",
    toolsets=["file", "terminal"]
)
```

### 上下文传递

每批需要包含：
1. **世界观文档** — 确保设定一致
2. **章节大纲** — 确保剧情走向一致
3. **前一批最后2章** — 确保风格和人物一致

### 超时处理

如果委托超时：
1. 检查已写完的章节数量
2. 从下一章继续委托
3. 将已写完的章节作为上下文传递

## 质量检查

### 每章检查

- [ ] 字数 ≥ 5000 字符
- [ ] 结尾有钩子
- [ ] 人物性格一致
- [ ] 世界观设定一致
- [ ] 与前文逻辑连贯

### 批次间检查

- [ ] 人物名称一致
- [ ] 修为境界一致
- [ ] 重要物品/事件一致
- [ ] 伏笔回收/埋设一致

### 全局检查

- [ ] 主线剧情连贯
- [ ] 人物成长弧线完整
- [ ] 伏笔有回收
- [ ] 节奏起伏合理

## 实战数据（no003 项目）

| 批次 | 章节 | 字符数 | 耗时 |
|------|------|--------|------|
| 1 | 1-3 | ~24,000 | ~150s |
| 2 | 4-6 | ~24,000 | ~150s |
| 3 | 7-9 | ~24,000 | ~150s |
| ... | ... | ... | ... |
| 10 | 28-30 | ~24,000 | ~150s |
| **总计** | **30章** | **~240,000** | **~1500s** |

> 注：原5章/批实验数据中，第6批（26-30章）超时，验证了3章/批更稳定。

**平均每章**: 8,365 字符
**平均每批耗时**: 480 秒（8 分钟）

## 文件命名规范

```
第001章-穿越与落地.md
第002章-坊市见闻.md
...
第030章-宗门初印象.md
```

- 3位数字零填充
- 中文连字符分隔
- 标题简洁（2-6字）
